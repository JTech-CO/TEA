# DOD_GUIDE.md — DoR / DoD 작성 가이드 + Phase 아키타입 해석

## 1. Definition of Ready (DoR) — 진입조건
phase를 시작하기 전 만족해야 하는 것. 충족 안 되면 시작 금지.
- 선행 phase의 DoD 게이트가 통과되어 있다.
- 필요한 환경·자원·접근이 준비되어 있다(`docs/ENVIRONMENT`).
- 관련 백서 절(`docs/`)과 불변식(`INVARIANTS.md`)을 확인했다.
- 측정이 필요한 phase면 계측 수단이 먼저 준비되어 있다.

## 2. DoD 작성 원칙
- **측정 가능해야 한다.** "규칙이 합리적이다"가 아니라 수치·통과/실패 이진값.
- **"규칙이 있다" != "규칙이 효과가 있다".** 효과를 직접 보는 게이트를 둔다.
- **불변식은 분리해 명시하고 INV-n로 인용.** 1건 위반 시 통과 금지.
- **반복과 분산을 함께 적는다.** 단일 실행 수치는 게이트 근거가 아니다.
- **재현 가능한 명령으로 검증.** 누가 언제 돌려도 같은 판정.
- **증거를 남긴다.** 통과 주장 시 명령·핵심 출력을 phase 파일/`PROGRESS.md`에.

## 3. TEA에서의 아키타입 해석
원본 팩의 아키타입 메뉴 9종 중 이 프로젝트에 해당하는 것과, 코드 프로젝트가 아니어서 달라지는 부분이다.

| 원본 아키타입 | TEA 적용 | 해석 차이 |
|---|---|---|
| 1. 기반/스캐폴딩 | M0 | 빌드·타입체크가 없다. 대신 **계측 스크립트와 예산 게이트**가 스캐폴딩이다 |
| 2. 핵심 도메인 로직 | M2, M3 | "순수 로직"이 규칙 문서다. 단위 테스트 대신 **문구 검사와 예산 검사** |
| 5. 핵심 기능 실효 검증 ★ | M1, M5, M6 | 이 프로젝트의 중심. 발화율과 기준선 대비 개선이 실효 지표 |
| 6. 통합/정합성 ★ | M5 | 정합성 대상이 두 구현이 아니라 **선행 공개치와 B군 재현치** |
| 8. 외부 연동 | M7, M8 | 호스트 어댑터·모드 연동·서브에이전트 스코프 |
| 9. 벤치마크/CI | M4 | 계측 하네스 구축 |

**미적용:** 3(데이터/영속화), 4(API/서버), 7(UI/프론트엔드). TEA는 서비스가 아니라 규칙 배포물이다.

## 4. 이 프로젝트 고유의 게이트 유형

### 4.1 예산 게이트
산출물이 정해진 토큰 예산 안에 있는지. 이진 판정.
> 예: `SKILL.md` 본문 ≤ 1,200토큰 (INV-3 준수)

### 4.2 발화 게이트
스킬이 의도한 상황에서 발화하고 의도하지 않은 상황에서 발화하지 않는지.
> 예: 양성 recall ≥ 5/6, 음성 precision ≥ 7/8, 문항당 3회 실행

### 4.3 개선 게이트 ★
기준선 대비 측정된 개선. **이 프로젝트에서 가장 중요한 게이트 유형이며, 5조건 AND다.**
> 예: 총 토큰 mean(C) < mean(B) 이고 차이 > 합성 표준편차, 턴 수 비증가, 재시도율 비증가, assertion 통과율 C ≥ B, 적대적 티어 100%

### 4.4 반증 허용
개선 게이트는 **통과하지 못할 수 있다.** 이는 phase 실패가 아니라 측정 결과다.

미달 시 처리 순서는 `HARNESS.md` §2.3. 요지: 계측 의심 → 규칙별 분리 → 그래도 미달이면 가설 반증으로 보고. **게이트 수치를 낮추거나 조건을 일부만 적용해 통과 판정을 내리지 않는다.** 이는 레드라인이다.

## 5. DoD 작성 시 흔한 오판
- "규칙 12개를 다 썼다" → 산출물 존재이지 게이트가 아니다
- "토큰이 줄었다" → 5조건 중 1개다. 나머지 4개 없이는 미완료(INV-7)
- "한 번 돌려봤더니 좋았다" → 반복·분산 없이는 증거가 아니다
- "B군 수치가 공개치와 다르지만 진행" → 재현 실패는 환경 문제일 수 있다. 먼저 규명한다
