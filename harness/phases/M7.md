# M7 — 플러그인 전환

> 근거: docs/TECHNICAL §5.3.2·§10.4, docs/DESIGN §2.3·§8. 전환 트리거는 커맨드 필요 시점 — 채택(M6) 이후에만. 아키타입 8.

## 목적
행동(스킬)은 그대로 두고 로딩 어댑터(플러그인)를 얹는다 — 커맨드·강도·Ponytail 연동.

## DoR (진입조건)
- [ ] M6 채택 판정 통과 (반증 시 이 phase는 착수하지 않는다)
- [ ] tea/가 호스트 의존 요소 없이 유지되어 있음 (FILE_TREE 경계 1)

## 할 일
1. .claude-plugin/plugin.json + hooks/hooks.json + commands/tea.md·tea-audit.md (DESIGN §2.3 트리)
2. 강도 3종 — light(THINK만)/standard(3축+경계)/strong(경계 좁게), 기본 standard (§8.1)
3. Ponytail 모드 연동 — 종속 기본(lite→light, full→standard, ultra→strong, off→standard), 독립 지정은 명시 오버라이드만 (§8.2). 미설치 시 P1 스텁 활성 + standard 고정 (§8.4)
4. 서브에이전트 스코프 — 탐색(읽기 전용): READ축+T3만 주입, 편집: 전체. WRITE축을 탐색 에이전트에 넣지 않는다 (§8.3, RUNBOOK #19)
5. /tea-audit — 소비 분포만 보고 (총량·비용은 caveman 위임, §8.5). M4 벤치마크 파서 재사용
