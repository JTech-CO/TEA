# M2 — SKILL.md 본문

> 근거: docs/DESIGN §2(구조·예산)·§4(규칙 카탈로그)·§3.3(지속성 선언), docs/TECHNICAL §5.4(근거는 축당 1회). 아키타입 2 — 단위 테스트 대신 문구 검사와 예산 검사.

## 목적
M1 확정 문안 + §4 카탈로그를 예산 내 본문으로 전개한 tea/SKILL.md를 얻는다.

## DoR (진입조건)
- [ ] M1 DoD 통과 (description 확정본 존재)
- [ ] rules/catalog.json 정합 (M0 DoD 6)

## 할 일
1. tea/SKILL.md frontmatter — name + M1 확정 description
2. 본문 전개 순서: 지속성 선언(§3.3) → 사다리 L1~L4 → 축 우선순위(THINK>READ, T3이 R1~R3에 우선 명시) → READ 근거+R1~4 → WRITE 근거+W1~5 → THINK 근거+T1~3 → 규칙 경계(§4.6 요지) → 금지 X1~4 → 불가침 5항목 → P1 스텁(Ponytail 미설치 시) → references/ 로드 조건
3. 근거는 축당 1회 2~3문장, 규칙은 명령형 1문장 + ID 표기
4. 영문 규칙 문안을 원장에 text_en으로 역기입 (원장-본문 동기)
