### 확정 기전 (적대 검증 반영)
- **초과 비용의 본체는 스킬 전달 라운드다.** Skill(tea) 호출은 95/95 세션에서 항상 첫 API 콜이며, 그 콜 하나가 기저 컨텍스트 1회분(sonnet ~33.8k / opus ~25.4k)을 통째로 재과금한다. 이어 본문(~945tok)이 별도 user 메시지로 주입되어 턴으로 계수된다
- **"페이싱 턴"은 존재하지 않는다** — 초과 비스킬 API 콜은 sonnet −0.21(오히려 감소)/opus +0.19. 도구 호출 구성은 B≈C(읽기는 C가 적음). 남는 격차는 콜당 컨텍스트 밀도(+1.3k/+0.9k)이며 be-archive 아웃라이어에 집중(노이즈 가능성)
- **어떤 단일 규칙 제거로도 판정은 뒤집히지 않는다** — 핸들별 반사실 최대 회수가 필요치의 절반에도 못 미치고, opus는 ③④⑤가 남아 이중 봉쇄. t1 상관 0.73은 단일 사건 산물(96건 중 1건), t2 0.74는 동어반복(무규칙 B군에서도 0.70)
- **규율 효과는 부분 실재** — sonnet 읽기 6.02→5.15·중복읽기 0.42→0.17, 기능 동등성 100% 유지. 절감 크기가 전달 비용의 ~1/20
- **주입형(M7) 전망**: Skill 콜 제거 시 C′−B ≈ +28~42k(평균 기준, 중앙값 기준은 0 부근). 채택 판정(5조건 AND × 2모델) 전환 확률 ≤1% — **재측정의 판정 목적 정보 가치 없음**
- **측정 주의 기록**: sonnet B 8건·C 3건이 서브에이전트를 사용했고 metrics가 사이드체인 비용을 비일관 누락 — 로그 합산 기준 sonnet ΔcacheRead는 +60~67k(보고치 +74k 대비 10~19% 과대). 부호·판정 불변. opus는 완전 일치. 중앙값 델타는 +23k/+30k로 꼬리 주도
- **부수 발견**: references 번들은 192개 B·C 세션에서 단 1회도 로드되지 않음 — 번들 비용 0, 동시에 번들 효용도 0
- 적대적 티어(⑤)는 NOT-RUN — 채택 가능성이 소멸했으므로 실행하지 않음(채택 시에만 필수)
