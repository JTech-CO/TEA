# INVARIANTS.md — 불변식 레지스트리

> 불변식은 "절대 일어나면 안 되는 일"이다. 일반 DoD와 달리, **1건이라도 위반되면 통과 금지**. DoD와 레드라인은 여기 ID(INV-n)를 참조한다. 새 불변식은 ID를 부여해 추가하고, 폐기 시 줄을 지우지 말고 상태를 `폐기`로 표시한다.

## 등록 규칙
- 검증 가능한 형태로 쓴다(명령·스크립트·자동 점검으로 확인되게).
- "범위"에 어느 phase에 적용되는지 명시.
- DoD에서 `(INV-3 준수)`처럼 인용한다.

## 레지스트리
| ID | 불변식 | 범위 | 검증 방법 | 상태 |
|---|---|---|---|---|
| INV-1 | 시크릿(`.env`·API 키·토큰)을 커밋하지 않는다 | 전역 | pre-commit 시크릿 스캔 | 활성 |
| INV-2 | 세션 로그 원본·벤치마크 아티팩트를 커밋하지 않는다 | M4~M6 | `.gitignore` 검사, CI 크기 점검 | 활성 |
| INV-3 | `SKILL.md` 본문이 1,200토큰을 넘지 않는다 | M2~M7 | `scripts/token-budget.js` 이진 판정 |  활성 |
| INV-4 | 어떤 규칙도 불가침 5항목을 축소하지 않는다 — 신뢰 경계 검증·예외 처리·데이터 손실 방지·보안·접근성 | 전역 | 적대적 티어 실행, C군 = B군 = 100% | 활성 |
| INV-5 | 규칙 문구에 "토큰"·"짧게"·"줄여라"가 등장하지 않는다. 규칙은 행동만 기술한다 | M2, M3 | 금칙어 grep + 문구 리뷰 | 활성 |
| INV-6 | ID와 측정 핸들이 없는 규칙이 0건이다 | M2, M6 | `scripts/rule-audit.js` — 규칙 수 == 핸들 수 | 활성 |
| INV-7 | 채택 게이트 5조건을 전부 충족하지 않으면 채택하지 않는다 | M5, M6 | `scripts/gate.js` AND 판정 | 활성 |
| INV-8 | LOC를 지표로 사용하지 않는다 | M4~M6 | 벤치마크 설정에 LOC 필드 부재 확인 | 활성 |
| INV-9 | 벤치마크는 3군(A/B/C) 구조를 유지하며, 순기여는 C−B로만 산출한다 | M5, M6 | 실행 매트릭스 3군 확인 | 활성 |
| INV-10 | 총 토큰 집계에 추론 토큰을 포함한다 | M4~M6 | 집계 스키마에 reasoning 필드 존재 확인 | 활성 |

## 불변식별 배경
근거가 되는 백서 절이다. 불변식을 완화하려는 시도가 있을 때 여기를 먼저 읽는다.

| ID | 근거 | 완화 시 발생하는 일 |
|---|---|---|
| INV-3 | TECHNICAL §5.1, DESIGN §2.2 | 자기 회수 실패. 스킬이 절감분보다 많이 먹는다 |
| INV-4 | TECHNICAL §7.4, §9.6 | 단순 축약 지시가 안전 항목을 먼저 희생시킨다는 선행 측정이 있다 |
| INV-5 | TECHNICAL §9.5, ADR-0005 | 목적 함수 동형성. 측정 밖 축으로 비용이 전가된다 |
| INV-6 | DESIGN §4.1 | 측정 불가능한 규칙은 제거 근거도 만들 수 없어 영구 누적된다 |
| INV-7 | TECHNICAL §8.4, DESIGN §7.1 | 총 토큰 단독 판정은 caveman이 실패한 경로다 |
| INV-8 | TECHNICAL §7.5 | Goodhart. LOC를 지표로 삼는 순간 골프가 자동 발생한다 |
| INV-9 | TECHNICAL §8.2 | TEA 단독 측정은 Ponytail이 처리한 계층 B를 자기 공로로 계상한다 |
| INV-10 | TECHNICAL §9.3 | 사다리 추론 비용 위험이 측정에서 사라진다 |
