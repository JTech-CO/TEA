# CLAUDE.md — TEA 에이전트 계약

> Claude Code가 세션마다 자동으로 읽는 최우선 문서. 여기 규칙이 다른 모든 지시에 우선한다. 상세 절차는 `HARNESS.md`, 불변식 본문은 `INVARIANTS.md`.

## 프로젝트 한 줄
에이전트가 컨텍스트를 쓰는 방식을 규율해 태스크 완료까지의 총 토큰과 턴 수를 줄이는 스킬을 만든다.

## 매 세션 행동
1. 먼저 `PROGRESS.md`를 읽어 현재 phase·다음 할 일·미결을 파악한다.
2. **한 번에 한 phase.** 해당 `phases/Mn.md`의 진입조건(DoR)을 만족할 때만 시작한다.
3. **완료 = 측정 가능한 게이트(DoD) 전부 통과.** "규칙이 그럴듯하다"는 완료가 아니다.
4. 게이트 통과를 주장할 때는 **명령과 출력을 증거로** phase 파일/`PROGRESS.md`에 남긴다.
5. 종료 시 `PROGRESS.md`를 갱신하고 커밋한다.

## 이 프로젝트의 핵심 함정
**규칙을 늘리고 싶은 충동이 이 프로젝트의 주된 실패 경로다.** 규칙 하나를 추가하면 계층 2 예산(INV-3)을 먹고, 사다리 판단 비용을 늘리고, 기여도 측정 대상을 하나 늘린다. 그럴듯해 보이는 규칙일수록 위험하다.

- 규칙 추가는 M6의 기여도 측정을 통과한 뒤에만 허용한다(INV-6).
- 규칙 문구에 "토큰"을 쓰지 않는다. 행동만 기술한다(INV-5, ADR-0005).
- "이 규칙이 도움이 될 것 같다"는 근거가 아니다. 측정 핸들이 없으면 규칙이 아니다.

## 레드라인 (절대 금지 — 위반 시 즉시 멈춤)
- 게이트 수치 임의 하향, 벤치마크 반복 횟수 축소, 통과 조건 5개 중 일부만으로 채택 주장.
- 불변식(`INVARIANTS.md`)이 깨진 채 다음 phase 진행.
- 지표에 LOC 도입(INV-8). 총 토큰 집계에서 추론 토큰 제외(INV-10).
- 3군 구조를 2군으로 축소하거나 TEA 단독 측정으로 순기여 주장(INV-9).
- 불가침 5항목(검증·예외 처리·데이터 손실 방지·보안·접근성)을 축소하는 규칙 작성(INV-4).
- 시크릿(`.env`)·대용량 산출물(세션 로그 원본·벤치마크 아티팩트) 커밋(INV-1·INV-2).

## 멈춤(STOP) — 다음이면 작업을 멈추고 보고한다
- 같은 실패를 서로 다른 방법으로 3회 시도해도 미해결.
- DoD 게이트를 못 넘는데 우회 충동.
- 불변식을 깨야만 통과 가능.
- **C군이 B군보다 나쁘게 나옴** — 규칙을 손대기 전에 보고한다. 이건 버그가 아니라 가설 반증일 수 있다.
- 외부 입력 부재(14섹션 목록, 검증 모델 2종).
→ 멈출 때 절차는 `HARNESS.md` §2.
