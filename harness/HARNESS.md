# HARNESS.md — 마스터 운영 매뉴얼

> "무엇을 만드는가"(백서)가 아니라 **"어떻게 진행·검증·복구하는가"(운영 규율)**. TEA에서 phase의 "완료"는 규칙이 그럴듯한 것이 아니라 **기준선(B군) 대비 측정된 개선**이다. 게이트로 막지 않으면 근거 없는 규칙이 누적되고, 누적된 규칙은 제거할 근거도 없다.

## 0. 세션 루프
1. 시작: `PROGRESS.md` → 현재 phase·다음 할 일·미결 → 해당 `phases/Mn.md` + 관련 `docs/` 절.
2. 작업: 한 번에 한 phase. 작업 단위마다 그 phase의 검증 명령으로 게이트 확인.
3. 종료: `PROGRESS.md` 갱신(완료 체크·증거·다음 할 일·새 미결·결정 링크) → 커밋.

### 0.1 완료 판정
DoD 항목이 **전부** 충족되어야 완료. 하나라도 미달이면 미완료로 두고 다음 phase로 가지 않는다.

M5·M6에서는 여기에 조건이 하나 더 붙는다. **채택 게이트 5조건은 AND다.** 총 토큰이 줄었다는 사실만으로 채택하지 않는다(INV-7). 근거는 `docs/TECHNICAL` §9.5 — 토큰만 보는 판정은 측정 밖 축으로 비용을 전가시키는 구조적 위험이 있다.

### 0.2 의존 순서
M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7 → M8.

M1(description)이 M2(본문)에 선행한다. 발화하지 않는 본문은 측정 대상이 되지 못한다. M4(계측)가 M5(측정)에 선행하는 것도 같은 이유다.

### 0.3 증거 기반 완료
게이트 "통과"를 주장할 때, 근거가 되는 **명령과 핵심 출력**을 해당 `phases/Mn.md`의 증거 칸과 `PROGRESS.md`에 남긴다. 증거 없는 완료 주장은 미완료로 본다.

**수치 증거에는 반복 횟수와 표준편차를 함께 적는다.** 에이전트 실행은 분산이 크다. 단일 실행 수치는 증거가 아니다.

## 2. 멈춤 규칙 (STOP)
### 2.1 멈춰야 하는 상황
- 같은 에러/실패를 서로 다른 방법으로 **3회** 시도해도 미해결.
- DoD 게이트를 못 넘는데 우회 충동.
- 불변식(`INVARIANTS.md`)을 깨야만 통과 가능.
- **측정 결과가 가설을 반증함** — C군이 B군보다 나쁘거나, 규칙 기여도가 음수로 나옴.
- 외부 제약(검증 모델 접근 불가, 대상 레포 변경, 14섹션 목록 미수령).

### 2.2 멈출 때 절차
1. `PROGRESS.md`에 기록: 증상 / 재현 방법 / 시도한 것들 / 가설 / 막힌 지점.
2. 사용자에게 요약 보고, 선택지가 있으면 제시한 뒤 결정 요청.
3. 결정 전까지 불변식을 깨는 임시 우회를 만들지 않는다.

### 2.3 반증은 실패가 아니다
2.1의 네 번째 항목은 특별 취급한다. **C군 열세는 버그가 아니라 결과일 수 있다.** 이때 규칙을 조정해 수치를 맞추려는 시도는 게이트 위장(레드라인)에 해당한다.

절차:
1. 먼저 계측을 의심한다 — 추론 토큰 누락, 3군 설정 오류, B군 재현 실패.
2. 계측이 정상이면 규칙별 기여도를 본다(M6). 특정 규칙이 원인인지 전체가 원인인지 분리한다.
3. 전체가 원인이면 **가설 반증으로 보고한다.** 규칙을 늘려 만회하지 않는다.

### 2.4 절대 금지 (레드라인)
`CLAUDE.md`의 레드라인과 동일.

## 3. 검증 우선순위 (한 줄)
불가침 유지 > 트리거 발화 > 기준선 대비 개선 > 규칙별 최적화 > 패키징.

앞 단계가 깨지면 뒤 단계는 의미가 없다. 불가침이 깨지면 개선 수치는 무효이고, 발화하지 않으면 개선을 측정할 수 없으며, 개선이 없으면 규칙별 최적화는 대상이 없다.
