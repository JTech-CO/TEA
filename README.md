# TEA — Token Engineering for Agents

AI 코딩 에이전트가 컨텍스트를 소비하는 방식을 규율해 태스크당 총 토큰과 턴 수를
줄이려던 스킬 프로젝트. **결과: 반증(채택 불가) — 2026-08-19 종결.**

## 결과 요약

3군 벤치마크 288트라이얼 (12태스크 × A/B/C × sonnet-5·opus-5 × n=4, $151.70):

| | A (스킬 없음) | B (Ponytail) | C (Ponytail + TEA) |
|---|--:|--:|--:|
| sonnet 총토큰 | 533,656 | 402,626 | **478,454 (+18.8%)** |
| opus 총토큰 | 616,627 | 313,301 | **367,091 (+17.2%)** |

채택 게이트(5조건 AND × 2모델) 미통과. 기능 동등성은 전 군 100%였고 규율 효과도
부분 실재했으나(중복 읽기 −60%), **스킬 전달 라운드가 기저 컨텍스트 1회분(25~34k)을
재과금하는 고정비**가 절감분을 압도했다. 단일 규칙 제거·주입형 전달 전환의 판정
전환 확률은 ≤1%로 산출됐다(적대 검증 3건 전부 판정 지지).

한 줄 교훈: **턴을 늘리는 최적화는 순손실이다 — 이 백서의 제1원칙(§2.3)이
백서 자신의 산출물을 걸러냈다.**

## 저장소 지도

| 경로 | 내용 |
|---|---|
| `docs/` | 기술 백서 v0.4 (반증 각주 + **부록 C: 후속 연구 가설**) · 설계 백서 · 환경 · 파일트리 |
| `harness/` | 운영 규율 팩 — phase별 DoD·증거, 불변식 10종, ADR 11건, 런북 23항 |
| `tea/` | 산출물 스킬 (SKILL.md 846tok + references 5종) — 트리거 게이트는 통과했으나 미채택 |
| `bench/` | **재사용 가치 최대** — 3군 러너·핸들 파서·집계기·게이트 판정기·소급 재채점기 |
| `scripts/` | 예산·금칙어·원장 게이트 + 트리거 평가 러너 |

## 재현

```bash
npm install && npm run selftest                # 게이트 자기시험
node scripts/gate.js --in <bench/results/...>  # 채택 판정 재현
node bench/contribution.js --in <...>          # 기여도 분석 재현
```

측정 재실행 절차와 실행 환경 고정은 `docs/ENVIRONMENT.md`, 판정 전문은
`harness/phases/M5.md`·`M6.md`. 후속 실험(장기·대형 세션, 주입형 전달)의
사전 등록 가설은 백서 부록 C.
